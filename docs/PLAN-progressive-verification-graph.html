Monitoring monorepo · M5 early local cutover

Remove the queue. Keep the quality bar.

M5 removes the mandatory local gate from the push path. Direct package feedback and hardened existing CI keep the quality bar. The design adds no app, cloud project, scheduler, task graph, or verdict store.

Reuse existing CI. Harden its authority.

Keep one required CI / ci aggregate, Code Quality, Sentry suites, Vercel, and Vercel Preview Comments.

Required pull request path

  • Fixed jobs and pinned path filter.
  • Unknown and control-plane paths select all conditional checks.
  • Closed-world aggregate rejects failed, cancelled, missing, and unexpected results.
  • PR jobs restore nonfatal trusted-main-v1 caches but never save.
  • An empty restore clears only its fixed cache target. The required setup command then runs cold.
  • pnpm keeps its executable and dependency cache in separate home-relative paths. Cache cleanup cannot remove pnpm.
  • Automated review, feedback ledger, current-head readiness, and operator-authorized GitHub merge remain.

Immutable no-skip audit

  • Workflow definition comes from protected main.
  • Dispatch inputs are PR number, full source SHA, and full base SHA.
  • Verify same-repository current PR head and current protected base at dispatch.
  • Check out both recorded objects. Do not resolve moving branch refs again.
  • Reuse the fixed CI jobs. Force every conditional job and reject every skip.
  • Reject package-execution and evidence-instrument drift before fan-out. Protect both focused contract definitions. Package drift can use full ordinary CI. Instrument drift cannot count as evidence.
  • Run two focused retained-contract suites. Skip only the four remaining legacy local-gate steps.
  • Forward no repository or environment secrets. Called jobs keep a scoped read-only GITHUB_TOKEN.
  • Disable every reviewed pnpm, Playwright, Foundry, and Turbo cache restore, save, and post hook.
  • Use a distinct run and display name. Record the run ID with its immutable inputs as operational evidence. It is not a PR check and cannot satisfy readiness.
M2 keeps this small: remove 11 unused checks: write grants. Replace schema, Terraform, and Lighthouse PR comments with read-only job summaries. Remove Claude OIDC authority. Keep only protected-main cache writers. Codecov, read-only Terraform plans, protected-preview Lighthouse, and Claude review retain the exact credential boundaries recorded in ADR 0078. The diagnostics artifact excludes them. The operator also accepted publication before rotation of the disclosed Vercel bypass token; rotation remains an IaC-owned follow-up. One structural checker follows local reusable workflows, inventories every pull request write or credential job with its exact permission and credential bindings, scans all cache saves, and pins each retained restore, targeted cleanup, and required setup command.
Canary spend is capped: allow at most 45 runner-minutes per no-skip run and 450 cumulative runner-minutes. Stop after a run exceeds 45 minutes. Do not start another run when it could exceed the cumulative ceiling. The first cold proof on PR #2199 used 43.48 runner-minutes. It exposed a wrong target: the audit repeated the full 20-job ordinary graph and included four legacy-heavy steps. The operator stopped it. It gives no cohort credit. The repair extracts the retained setup, package-policy, and autoreview assertions into two focused suites. It excludes only the four legacy selector steps. Retained generated-output and workflow safeguards still run in fixed CI. The post-cutover canary starts after M5 reaches protected main. Audit-eligible pull requests use ordinary CI plus no-skip for the same immutable head. Package, dependency, and toolchain pull requests use ordinary CI only when the protected filter selects the full fixed job set and every retained job succeeds. Evidence-instrument changes cannot count. At least 10 merged pull requests over at least 7 calendar days must pass these rules. The no-skip ceiling has 43.48 of 450 runner-minutes recorded.
Trusted-candidate limit: GitHub gives dispatched jobs cache-service authority outside the workflow permissions map. The reviewed workflow disables every known cache path. It cannot sandbox malicious same-repository candidate code that calls the cache service directly. The accepted trusted-contributor model bounds this residual.

Seven inventory dispositions

  • retained-required-ci: required CI.
  • retained-author-procedure: author procedure.
  • retained-after-merge: after merge.
  • scheduled: stated interval.
  • duplicate: named retained safeguard.
  • obsolete-with-evidence: proved obsolete.
  • deferred-with-owner: owner and follow-up.

Rollback before deletion

On a confirmed author-check mapping omission, stop merge handoffs and revert the cutover commit. Keep required CI and strict current-base protection.

Rollback after deletion

Revert retirement first. Restore and verify runtime, coordinator, tests, process safeguards, and run.lock. Re-enable the hook only after its runtime exists.

Mixed worktrees: the snapshot has 25 registrations. Keep legacy run.lock while an active supported worktree can run the old gate. Never use --no-lock or clear coordinator state.

Complexity is a release condition.

The plan removes a local control platform. It must not build a remote replacement.

Allowed additions

  • Small filter and aggregate contract tests.
  • One thin orchestration script below 300 non-test lines if needed.
  • A reviewed inventory and generated before/after manifest.
  • Existing workflow jobs and schedules.
  • M2 deletes comment writers instead of adding publisher jobs.

Explicitly excluded

  • GitHub App or GCP project.
  • Service, database, queue, daemon, signer, or verdict store.
  • Dynamic DAG, task registry, receipt schema, or cache protocol.
  • New cross-worktree lock, socket, lease, journal, or port owner.
