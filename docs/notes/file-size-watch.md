# File-size and lint-hygiene watch list

This is passive guidance, not an active-work queue. Refresh it with
`node scripts/repo-health/file-size-watchlist.mjs`; use `--format issue` when a
concrete
split is ready for GitHub Issues.

`.github/workflows/file-size-watchlist.yml` owns the monthly cadence. It checks
out current `main`, runs the checked-in reporter, and opens or updates one
marked issue only for effective hard/near-hard rows or material growth above
the effective soft cap. Raw growth and rough cap status stay separate. Do not
run a second external monthly scheduler in parallel.

For a live scheduler check, dispatch the workflow with `publish_report=true`.
That option publishes the same current-main report as a closed evidence issue
when no actionable drift exists:

```bash
gh workflow run file-size-watchlist.yml --ref main -f publish_report=true
```

The reporter emits a second table only while
[ADR 0065](../adr/0065-scripts-file-size-watchlist-scope.md) lists an exemption:
a `scripts/` file whose split would change a named mechanism rather than
refactor a file. Exempt files never open an issue, and the reason travels with
each so nobody re-litigates it. The list is currently empty, so the report below
carries no second table. Refresh this file when the scope or the exemptions
change — without a current baseline every soft-cap row reads as new drift.
